# DnDisc

Кроссплатформенный аудио-плеер, микшер окружения (амбиентов) и саундборд, созданный специально для Мастеров Подземелий (Game Masters) в настольных ролевых играх (TTRPG).

## 🚀 Основной функционал

*   **Трехслойный аудио-движок:** Раздельные шины для фоновой музыки (`Music`), зацикленных звуков окружения (`Ambient`) и разовых звуковых эффектов (`SFX`).
*   **Управление сценами (Scenes):** Сохранение и быстрая загрузка пресетов (музыка + настройки амбиентов) для различных локаций (например, "Шумная таверна", "Мрачное подземелье", "Бой с боссом").
*   **Продвинутое аудио-управление:** 
    *   **Ducking:** Автоматическое приглушение музыки при воспроизведении важных звуковых эффектов (SFX) или речи.
    *   **Fading:** Плавные переходы и затухания (Crossfade) при смене треков или сцен.
*   **Саундборд (Soundboard):** Сетка с кнопками для быстрого запуска заранее подготовленных звуковых эффектов.
*   **Локальная библиотека:** Хранение метаданных загруженных треков с использованием локальной базы данных (SQLite).

## 🛠 Технологический стек

*   **Фреймворк:** Flutter (Desktop - Windows/Linux, кроссплатформенность)
*   **Стейт-менеджмент:** `provider` (ChangeNotifier)
*   **Аудио:** `flutter_soloud` (высокопроизводительный движок) и `audioplayers`
*   **Хранение данных:** `sqflite` / `sqflite_common_ffi` (для десктопа)
*   **Файловая система:** `file_picker`, `path_provider`

## 🏗 Архитектурные правила и стандарты проекта

В проекте установлены строгие правила для обеспечения стабильности аудио-движка на десктопе:

1.  **Прямой вывод логов в CLI:** Все события аудиосистемы, ошибки и изменения громкости дублируются в терминал (`stdout.writeln` / `stderr.writeln`) с таймштампами.
2.  **Асинхронность:** Аудио-драйверы работают асинхронно и не блокируют основной UI поток (Dart Event Looper).
3.  **Валидация файлов:** Перед отправкой локального пути в плеер всегда проверяется его физическое существование через `File(filePath).existsSync()`.
4.  **Сквозная реактивность:** Все аудио-контроллеры (Music, Ambient, SFX) проксируют события в корневой `MultiProvider` для мгновенного обновления UI.

### 🧪 Стандарты тестирования

Все тесты (Unit, UI, сервисы) имеют строгую трёхкомпонентную структуру описания:
1.  **Что проверяем** (модель, метод, виджет).
2.  **Входные данные** (состояние, аргументы, моки).
3.  **Ожидаемый результат** (утверждения, вызовы коллбэков).

*Пример:* `Что проверяем: Установка громкости в MusicBusController. Входные данные: setVolume(0.75). Ожидаемый результат: effectiveVolume становится 0.75 и вызывается notifyListeners.`

```bash
# Запуск на Windows (или linux)
flutter run -d windows
```
