# Стандарт документирования и структуры тестов

При написании любых тестов (Unit-тесты моделей, аудио-контроллеров, базы данных SQLite, сервисов и UI виджетов) необходимо строго следовать единому формату:

## 1. Трёхкомпонентная структура каждого теста
Каждый тест (`test()`, `testWidgets()`) должен содержать в названии или в первом блоке описания 3 обязательных пункта:
* **Что проверяем:** Конкретный класс, метод, алгоритм или сценарий взаимодействия в UI.
* **Входные данные:** Исходное состояние моделей, переданные аргументы, настройки громкости или действия пользователя.
* **Ожидаемый результат:** Конечное состояние системы, возвращённые значения или утверждения `expect()`.

## Пример правильного оформления теста:
```dart
test(
  'Что проверяем: Установка громкости в MusicBusController. '
  'Входные данные: setVolume(0.75). '
  'Ожидаемый результат: effectiveVolume становится равным 0.75 и вызывается notifyListeners.',
  () {
    final controller = MusicBusController();
    controller.setVolume(0.75);
    expect(controller.rawVolume, 0.75);
  },
);
```
